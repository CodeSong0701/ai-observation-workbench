# 工作台演示录制脚本

建议录制时长：约 6 分钟。使用桌面浏览器录屏，保留页面筛选条件、运行状态和刷新后的结果。

| 时间 | 操作 | 讲解重点 |
| --- | --- | --- |
| 0:00–0:45 | 打开工作台，选择“替换数据集”，导入题目 ZIP 并确认。 | 本数据包为合成数据；平台名只是维度标签。导入后检查 12 个资产、3 个平台、4 个日期及 144 个应有业务任务。 |
| 0:45–1:35 | 按品牌、产品、平台和日期筛选任务列表，翻到第二页。 | 总览按逻辑业务键计数；重复 attempt 保留历史，但不会重复增加应有任务数。 |
| 1:35–2:25 | 打开 `P001|ChatGPT|2026-10-10` 的任务详情。 | 查看用户提问、原始回答、来源链接、分析证据和执行历史；解释“有效完成”要求证据可追溯。 |
| 2:25–3:15 | 对一条已有原始回答的任务运行 Mock 重新解析。 | 展示排队/处理/完成状态和结果刷新；明确标示这是 Mock，不是 ChatGPT 平台调用。 |
| 3:15–4:20 | 运行巡检并查看异常列表。 | 选取缺失任务、卡住任务和统计快照差异说明分类依据；T+2 截止按任务的 `analysis_due_at` 判断。 |
| 4:20–5:15 | 对缺失的 `P001|ChatGPT|2026-10-10` 运行模拟补采。 | 展示离线 recovery fixture 创建新 attempt、回答和分析，不接触真实第三方平台。 |
| 5:15–5:45 | 刷新页面并重新打开同一任务。 | 确认补采后的状态和分析已写入 SQLite，说明刷新后仍可查。 |
| 5:45–6:15 | 展示架构说明。 | 当前使用 FastAPI、SQLite 和轻量持久化 Runner；每天 10 万任务时再迁移到 PostgreSQL 与队列 Worker。认证和租户隔离列为对外部署前工作。 |

## Live 模式说明

本次交付环境没有配置 `OPENAI_API_KEY`，因此没有执行真实模型 API 调用。演示中的重新解析必须保持 Mock 标识，不得表述为 Live 结果。若录制环境配置了密钥，可将第 2:25–3:15 段另录一次 Live 调用，并确认详情显示 Live 模式；不要将密钥录入画面或提交到仓库。
